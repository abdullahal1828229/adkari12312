# ورد اليوم

تطبيق ويب هادئ يضم أكثر من ٢٢ بابًا من الأذكار والأدعية (٣٥٤ ذكرًا) — الصباح، المساء، بعد الصلاة، الرقية الشرعية، أسماء الله الحسنى، أدعية القرآن والأنبياء والنبي ﷺ، الحج والعمرة، وغيرها — مع عدّاد تفاعلي لكل ذكر يحفظ تقدّمك، ومفضلة، ومسبحة حرة. كل شيء يُحفظ محليًا في متصفح الزائر عبر localStorage، بلا أي خادم أو قاعدة بيانات — موقع ثابت بالكامل.

## التشغيل محليًا

```bash
npm install
npm run dev
```

## البناء يدويًا

```bash
npm install
npm run build
```

الناتج يكون في مجلد `dist/`.

## النشر على GitHub Pages (تلقائي)

المشروع يحتوي على ملف `.github/workflows/deploy.yml` يقوم بالبناء والنشر تلقائيًا في كل مرة تدفع (push) فيها إلى فرع `main`.

خطوات التفعيل لأول مرة:

1. أنشئ مستودعًا (repository) جديدًا على GitHub وارفع محتوى هذا المجلد إليه:
   ```bash
   git init
   git add .
   git commit -m "نشر ورد اليوم"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPO-NAME.git
   git push -u origin main
   ```
2. من إعدادات المستودع على GitHub: **Settings → Pages**، واختر تحت **Build and deployment → Source** الخيار **GitHub Actions**.
3. انتظر انتهاء تنفيذ الـ workflow (تبويب **Actions** في المستودع). بعد اكتماله سيظهر رابط الموقع في نفس الصفحة (Settings → Pages)، وعادة يكون بالشكل:
   ```
   https://USERNAME.github.io/REPO-NAME/
   ```

> ملاحظة: الـ workflow يضبط المسار الأساسي (base path) تلقائيًا ليطابق اسم المستودع، وهذا ضروري لأن مواقع مشاريع GitHub Pages تُنشر تحت مسار فرعي وليس على الجذر. لا حاجة لأي تعديل يدوي.

## صفحات مستقلة لكل قسم + خريطة الموقع (SEO)

بالإضافة إلى تطبيق الصفحة الواحدة، يحتوي `public/posts/` على **22 صفحة HTML مستقلة وقابلة للفهرسة كاملةً** (نفس أسماء الروابط القديمة، مثل `posts/sabah.html`، `posts/masaa.html`...) تعرض نص كل الأذكار مباشرة في المصدر (بدون الحاجة لتشغيل جافاسكريبت لقراءتها)، مع:
- عنوان ووصف Meta وrobots وOpen Graph مخصصة لكل صفحة، ورابط canonical.
- عدّاد تفاعلي وزر مفضلة يعملان بجافاسكريبت بسيط (`public/posts/dhikr.js`) ويستخدمان **نفس مفاتيح التخزين المحلي** التي يستخدمها التطبيق الرئيسي (`wird-counts`, `wird-favorites`)، فتبقى البيانات متزامنة بين الصفحات والتطبيق.
- روابط داخلية بين كل الأقسام (وسابق/تالي) لتسهيل زحف محركات البحث.

كذلك تم توليد `public/sitemap.xml` (يضم الرئيسية + الـ22 صفحة) وتحديث `public/robots.txt` للإشارة إليه. كل هذه الملفات داخل `public/` فتُنسخ تلقائيًا إلى `dist/` عند البناء وتُنشر مع كل push دون أي تعديل إضافي على الـ workflow.

بعد النشر، يمكنك تسجيل الموقع في [Google Search Console](https://search.google.com/search-console) وإرسال `https://adkari.org/sitemap.xml` لتسريع الفهرسة.

## صفحة 404 المخصصة

الملف `public/404.html` هو صفحة "الصفحة غير موجودة" بنفس هوية الموقع (الألوان والخط والعبارة الختامية). بما أنه داخل مجلد `public/`، فإن Vite ينسخه تلقائيًا إلى جذر مجلد البناء `dist/` عند كل `npm run build`، وبالتالي فإن الـ workflow (`deploy.yml`) يرفعه تلقائيًا مع بقية الموقع دون أي خطوة إضافية — وGitHub Pages تستخدمه تلقائيًا كصفحة خطأ لأي رابط غير موجود على الدومين المخصص.

## ملاحظة حول الأجزاء غير المستخدمة

المستودع الأصلي كان مشروع Replit متعدد الحزم (monorepo) يتضمن خادم API وقاعدة بيانات Postgres، لكن واجهة "ورد اليوم" لا تستخدم أيًا منهما فعليًا — كل البيانات (الأذكار، الأقسام) مضمّنة في الكود، والمفضلة وعداد المسبحة يُحفظان في localStorage. لذلك تم تحويل الواجهة فقط إلى مشروع مستقل قائم بذاته، وهو ما يعمل بشكل كامل على GitHub Pages كموقع ثابت (static site).
